# Browser editor checks

Serve `editor-checks.html` from a temporary development host that also serves `/_content/StickerApp.Shared`. Open it in the built-in local browser; it reports PASS or the first failed assertion. No external browser or automation dependency is needed.

For an isolated check, create `/tmp/stickit-editor-check/wwwroot`, copy this HTML there, build `StickerApp.Web`, then run its DLL with `ASPNETCORE_ENVIRONMENT=Development`, `--contentRoot /tmp/stickit-editor-check`, and a free localhost URL. Open `/editor-checks.html` at that URL. The temporary content root keeps manual UI-test imports separate from the personal library. Do not add the check page to production assets.

The page generates no library writes. It checks actual image/animation modules with a two-frame fixture, including cutout masks on every frame, recoverable opacity, PNG/replayed-frame agreement, animated WebP re-editing, partial transparency, layer apply/undo/redo/export/reopen, and isolated worker/main-thread cancellation. The standard storage checks separately verify saved composition data.

Animation-to-layer handoff checks verify transformed frame pixels and timing, working animations above the final 500 KB budget, and cancellation after main-thread encoding has begun. Final sticker export checks retain their existing size constraints.

`video-timing-checks.mjs` runs with Node and checks MP4 sample timing, variable-rate frame selection, unsupported native timing and conversion preflight budgets. `foreground-checks.html` verifies that the processing menu follows actual jobs, backgrounding terminates a worker, hidden work is rejected and the same session can retry on return. The feature suite also exercises preparation cancellation before editing, queued-image locks, foreground resume and native download cancellation.

Native timing reads ordinary MP4/MOV sample tables. Unsupported or fragmented containers require a fixed frame rate. Direct WebP uses millisecond timing, supports source rates up to 125 fps, and merges partial edge fragments shorter than the 8 ms sticker minimum. Video inputs are limited to 20 MB, selected clips to 5 seconds / 100 frames, and final WebP output to 500 KB.

Video size feedback samples at most six selected frames using the same 512px WebP encoder as final output. Sampling uses cancellable workers and returns a low/high size range plus a starting quality recommendation. Actual conversion enforces the final size limit before returning; it can retry at lower quality and never imports oversized output. Estimates cannot guarantee unsampled content. `video-size-estimate-checks.mjs` checks range math and quality selection.

The production video path writes animated WebP directly. It preserves the 1/2/4 worker preference (default 2), caps concurrency by reported hardware threads and actual frame count, transfers pixel buffers, and bounds in-flight frames. The output is centered in 512×512 without enlarging small sources. Exact duplicate consecutive frames share their combined duration; still-looking clips retain two animation frames. There is no intermediate GIF or subsequent automatic preparation step.

`video-import-checks.html` verifies real encoder output, color/timing, centering, the 500 KB limit, worker preferences, non-worker fallback, and abort/retry. Worker tracking asserts that backgrounding during conversion **and size sampling**, and successful completion, leaves no active workers. The same fixture verifies existing GIF import and duplicate-frame merging. `frame-dedup-checks.mjs` covers exact pixel comparison and duration-preserving minimum frame count. `video-worker-settings-checks.mjs` covers persistence and hardware caps.

Existing GIF import keeps its separate 20 MiB input limit. Preparation skips encoding duplicate consecutive composited frames, preserving playback timing, visual pixels and source backups. The normal editor fixture continues to exercise GIF cutouts, seeking, trimming, layer handoff and WebP re-editing. Feature checks cover cancelled library saves and ensure direct animated WebP enters the library ready, without another preparation job.

Performance recording is opt-in under Settings → Developer → Diagnostics & error logs. It records completed operation durations, retains the newest 100 rows in memory and includes records in the bounded diagnostic log. There is no sampling timer or continuous CPU/battery monitoring. Totals include nested steps; failures and cancellation also produce elapsed-duration records. Measure on the affected phone before drawing conclusions from desktop results.

`video-performance-checks.html` compares production direct WebP with 1/2/4 workers against a test-only legacy GIF→WebP route. It uses the same generated 232×512 clip, three runs at 2 seconds / 12 fps, and checks output duration, 512×512 dimensions and the 500 KB budget. These desktop measurements do not establish phone performance or visual-quality equivalence.

After integrating direct worker encoding, the generated-clip desktop comparison measured median times of 758 ms for the legacy test-only GIF→WebP path, 371 ms for direct WebP with one worker, 212 ms with two, and 184 ms with four (three runs each). Direct output was 94,618 bytes versus 105,102 bytes for the legacy path. These are warmed, small synthetic desktop results, not phone battery measurements or guaranteed speedups. The original GIF still-import/edit checks also pass.

Pinterest imports stage all selected sources before video review. Review stores source Blobs and clip settings without full conversion; the final summary starts one mixed video/GIF batch. At most two decoders run concurrently, dividing the configured total worker allowance between videos; GIFs use one worker per lane. Cancellation, foreground loss, failure and disposal release all active workers. The library commit remains atomic after all outputs pass sticker validation.

Run `video-batch-checks.html` for real mixed-media conversion, 1/2/4-worker total caps, cancellation/background/failure cleanup and first-frame PNG pack covers. `node tools/EditorChecks/preparation-cancellation-checks.mjs` verifies the preparation cancellation path calls worker termination and interrupts the old-WebView image-decoding fallback. A synchronous main-thread encoder call cannot be preempted, but cancellation checks prevent later encoding attempts.

Pack deletion keeps stickers by default. The optional library deletion removes the pack's stickers from every pack that references them and deletes their current/source/composition files. Preparation is cancelled before removal, and queued snapshots cannot restore or process deleted stickers. Feature/storage checks cover shared memberships, unrelated-file retention, pending encoder replies and atomic import cancellation.
